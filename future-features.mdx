Kyrou's active roadmap lives in **`docs/roadmap/`**. Treat that folder as the source of truth; this page is only a scannable public summary. Current shipped Kyrou remains local-first and account-free by default.

**2026-09-04 design port:** Kyrou's UI and data layer were rebuilt as a mechanical port of a Claude
Design app (see [Orientation](/orientation)); data lives in IndexedDB through `KyrouStore`.
Tasks, projects, routines, the routine day log, and routine runs sync when you are signed in.

**2026-09-14 (Milestones D1 and D2) shipped:** the shared sync-status projection, Ctrl/Cmd+S, the
sidebar account menu, lapsed sign-in (an expired session keeps your account's tasks visible instead
of signing you out), and a **Conflict review** modal reachable from "Review conflicts" rows — see
[Settings & Updates → Conflict review](/features/settings-updates#conflict-review). A change the
server rejects is now surfaced (undone-and-toasted, or kept local-only and toasted) instead of
silently dropped.

**2026-09-14 (Milestone D3) shipped:** the multi-edit conflict fix — two unsynced edits to the same
field on this device no longer overwrite another device's edit to it before a conflict ever shows up
to resolve, fixed on the client rather than the Worker. The **Conflict review** modal is now fully
keyboard-operable (Tab, arrow keys, Enter/Space, Esc) and no longer crashes when you pick a side. An
**offline shell** — a versioned service worker that caches the app itself — shipped too, verified
against a local production build; hosting the web build publicly (so this matters outside your own
machine) is Milestone E. Still ahead in the same sync-reliability track (item 12):

- **Switch account:** deferred — Google's managed sign-in re-signs silently with no per-call
  account-chooser prompt, so switching accounts needs its own design.

**2026-09-14/15 (Milestone E):** production Worker/Neon origins are wired up for the packaged
desktop app. Kyrou is decided desktop-only (2026-09-15) — no public web hosting is planned. The
hand-run acceptance matrix passed; one known gap remains open rather than fixed here: after a
production database restore, a device's resnapshot can leave rows the restore rewound as
permanent local-only orphans (never re-pushed, never seen by other devices) — see
`docs/roadmap/19-known-bugs.md`, tracked in a GitHub issue.

The current sequence is release-first: make sync reliable, gather real feedback from prospective PMF users and the ICP, then monetize only after the retention loop is credible.

## Roadmap Invariants

- **Local-only remains permanent.** Kyrou works without an account today, and optional accounts must not turn local planning into a trial.
- **Sync is optional and explicit.** Desktop discovers Sync from the sidebar; mobile discovers it from the top app bar. Settings -> Sync manages it, but first-time OAuth starts only after Continue with Google.
- **Free local core stays free.** Local planning and recurring tasks are free; sync has a 30-day trial and then belongs to Kyrou Pro.
- **Kyrou Pro is priced plainly.** The planned Pro tier is $5/month for reliable ongoing sync and service-backed power features.
- **Deferred platform ideas stay deferred.** Older platform/distribution work, focus tracking, overlays, Android widgets, and iOS follow-up live in `docs/deferred-roadmap/`.
- **Feedback steers polish.** UI improvements come after release feedback, not before the learning loop.

For exact task-level detail, open the numbered file for the active item in `docs/roadmap/`.
