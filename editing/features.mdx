## What changed

The pre-port workflow (add a field to `src/types/task.ts`, bump the Dexie schema in
`src/db/index.ts`, add a typed function to a repository, consume it via a `useLiveQuery` hook, put
new UI under `src/features/{feature}/`) no longer applies. That whole stack — `src/types/`,
`src/db/`, `src/stores/`, `src/features/` — was deleted in the 2026-09-04 design port (see
[Orientation](/orientation)). This page describes the current workflow.

## The current shape, end to end

Every page/panel/modal in the app is a **mechanical port** of one file in
`design-import/kyrou-app/` — Seji's hand-built Claude Design app is the source of truth, not a
spec you improvise from. There is no "add a new feature folder" step; new UI work starts in the
Claude Design project, not in code.

1. **The design file** — `design-import/kyrou-app/<Name>.dc.html` is what the ported component's
   markup, styling, and behavior must match one-to-one. Never invent markup that isn't there.
2. **The component** — `src/app/<Name>.tsx`, a React class component (`extends Component<Props,
   any>`), plus a sibling `src/app/<Name>.css` when the source file's `<style>` block was
   non-empty. `render()` reads `const v: any = { ...this.props, ...this.renderVals() }`.
3. **Data** — read and write through `src/kyrou/store.ts`'s exported `KyrouStore` object
   directly (e.g. `KyrouStore.dayTasks(dayKey)` to read a day's tasks, `KyrouStore.setTasks(dayKey,
   items)` to write them back), not through a repository or a reactive query hook. To re-render on
   every store change, subscribe with `KyrouStore.subscribe(fn)` (returns an unsubscribe function)
   or listen for the `kyrou:*` `CustomEvent`s it dispatches on `window` (`kyrou:history`,
   `kyrou:restore`, `kyrou:toast`, ...). `KyrouStore` is a single synchronous module over one
   `localStorage` record (`kyrou:data:v1`) — there is no async repository layer to route through.
4. **Shared behavior** — reuse the existing engine modules in `src/kyrou/*` (recurrence, routines,
   projects, parsing, undo/toast, theming, etc.) instead of re-implementing logic the design
   already has ported. Reuse `src/ds/*` for shared UI (`Badge`, `Button`, `Checkbox`, etc.).

### Worked example: the real toggle-and-write-back pattern

`src/app/Today.tsx`'s `_setDone(id)` (line 3717) is the real pattern a ported page uses to flip a
task's `done` flag — it mutates local state, not the store, directly:

```ts
// src/app/Today.tsx
_setDone(id: any) {
  this.setState((st: any) => ({
    items: st.items.map((x: any) => x.id === id ? Object.assign({}, x, { done: !x.done }) : x)
  }));
}
```

The store write isn't inline in that method. `Today`'s `componentDidUpdate` diffs
`this.state.items` against the previous render and, when they differ, calls
`KyrouStore.setTasks(this.state.dayKey, items)` — so the write happens once state settles, not on
every keystroke of a mutation. A simpler new page without that diff/write-back split can just call
`KyrouStore.setTasks(this.props.day, items)` directly inside its own toggle method —
`this.props.day` is `Today`'s real `day?: string` prop.

If `Today.dc.html` doesn't have the behavior you're adding, it isn't a port anymore — go add it to
the Claude Design project first, then re-port the affected file, rather than diverging from the
design in code alone. Any deliberate, disclosed deviation from the design source gets a
`// PORT-NOTE:` comment.

## Store vs. desktop settings

`src/kyrou/store.ts` (`KyrouStore`) holds all domain data — tasks, inbox, projects, routines,
routine log/runs, undo/redo history. `src/tauri/settingsStore.ts` is a small Zustand store that
holds only three desktop preferences (`startOnStartup`, `minimizeToTray`, `updateCheckOnStartup`)
— never domain data. If it's a task/project/routine, it belongs in `KyrouStore`; if it's a desktop
toggle, it belongs in `settingsStore`.

## Tests

Render-smoke tests live in `src/app/__tests__/` (e.g. `pages12.test.tsx`, `modals13.test.tsx`).
`src/app/__tests__/seed.ts` seeds `kyrou:data:v1` in `localStorage` before each test file runs.
Because `store.ts` reads `localStorage` at module-evaluation time, any component under test that
touches the store must be **dynamically imported after `seed()` runs**, not statically imported at
the top of the file — a static import sees a blank store.

## Before considering a change done

- `npm run test` (`vitest run`) — tests pass
- `npm run lint` — oxlint clean
- `npm run build` — `tsc -b && vite build` succeeds
- `grep -n "window\.Kyrou\|{{" src/app/<YourFile>.tsx` — empty, aside from the declared window
  flags in `src/global.d.ts` (a leftover `{{ }}` or `window.KyrouX` means the port missed a spot)
