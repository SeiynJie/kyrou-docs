## What it does

The Today screen (`/today`) is the main daily planner. It has three modes, switchable via the view tabs (or the `Shift+C` shortcut, which cycles Planner -> Calendar -> Markdown): a **Planner** list view, a **Calendar** time-grid view, and a **Markdown** freeform text view of the same day's tasks. All three modes read and write the exact same `tasks` table — there is one source of truth, just three lenses on it.

Alongside the main panel, a **Backlog sidebar** lists tasks that are overdue or have no date, so you can drag them onto today.

## Key concepts / how it connects

- **One data source, three views.** Planner, Calendar, and Markdown all call the same repository functions from `src/db/repositories/taskRepository.ts` (e.g. `useTodayTasks()`). Editing a task's time in Calendar mode and then switching to Markdown mode shows the change instantly — there's no separate "markdown state" to sync.
- **Markdown mode is a serialization, not a separate model.** `src/lib/taskMarkdown.ts` and `src/lib/markdownSave.ts` convert between the `Task[]` array and a markdown text blob (and back on save). Task IDs are embedded as hidden markers (stripped from view by `hideIdMarkers.ts`) so edits can be matched back to the right database row.
- **Today's heading is always there.** Opening Markdown mode on a day with no tasks used to give you a blank document — and since a task line must sit under a `## <date>` heading to save at all, there was nothing useful to type. `serializeTasks` now takes an opt-in `ensureToday` flag that seeds today's heading plus a ready `- [ ] ` line. The flag defaults to *off* on purpose: `MarkdownView` also calls `serializeTasks` to append newly-created tasks to an already-dirty document, and injecting there would emit a second today heading. A blank `- [ ] ` with no ID marker parses to nothing rather than an error, so the placeholder never blocks Save and simply disappears when the document re-serializes after saving.
- **Leaving Markdown mode with unsaved changes** is guarded: `uiStore` tracks a `markdownDirty` flag; `MarkdownLeaveGuard` (mounted globally) intercepts route/view changes and prompts before discarding edits.
- **Backlog membership is date-based, not status-based.** `getBacklogTasks()` in `taskRepository.ts` returns tasks that are either undated or have a date before today and aren't done — there's no separate "backlog" flag on a task.
- **Task detail: Status/Priority/Duration/Scheduled live together in one metadata grid.** Scheduled uses the existing M3 `DatePicker` in a portaled, viewport-clamped nested popover; choosing a date commits `YYYY-MM-DD`, and Esc closes the picker before the sheet. End time is editable — changing it adjusts duration (start time never moves); an end at or before start is rejected. Duration text can be temporarily empty while edited, but empty, invalid, or below-minimum blur/Enter values restore the stored duration instead of becoming 30 minutes.
- **Subtasks are real task rows, not an embedded list.** A subtask is a `tasks` table row with `parentId` set to its parent's id. It renders through the exact same `TaskCard` as a top-level task (an indented/compact variant), so it gets the full right-click context menu, natural-language date parsing on create and rename (e.g. typing "call mom tomorrow 3pm" as a subtask title), keyboard navigation, and drag/resize for free — there is no separate subtask component. Only one nesting level is allowed. `Turn into task` promotes a subtask to standalone; demoting a task back into a subtask uses the parent picker and blocks self-parenting or demoting a task that already has children of its own.
- **Subtasks schedule independently of the parent.** A subtask carries its own `date`/`startTime`/`duration`. A subtask with both date + time **graduates out** of the parent's nested checklist and renders as its own block in the Today list (bucketed by start time, keeping the `↳ parent` hint and the parent's project color) — the done/total count still spans all subtasks. Unscheduled subtasks stay nested and also appear as draggable chips in the calendar's unscheduled header row (own date, else parent's date, else today). If every subtask is scheduled, the parent card shows no expand toggle at all — it looks like a normal task. Scheduling a subtask by typing a time inline auto-fills a missing date (own > parent > today), so it always lands on a visible day.
- **Completion cascades both ways.** Marking a parent done marks every subtask done; toggling any subtask recomputes the parent (all subtasks done marks the parent done; reopening any subtask reopens the parent). Deleting a parent deletes its subtasks too.
- **Promoted subtasks carry their own date.** A subtask dragged out of its parent (promoted) can be scheduled to a different day independently of the parent via right-click → Move to Today / Schedule, Shift+Left/Right in a week column, or dragging it to another day's column. The subtask stays linked to its parent (parent shows an "N promoted" badge), renders as its own row on its scheduled day, and completing/editing it updates the parent. Moving the parent leaves dated subtasks where they are; undated promoted subtasks follow the parent. Dropping a promoted subtask back into the parent, reparenting, or sending it to the backlog clears its date.
- **Drop targets show where a card will land.** Dragging a task card or a subtask (nested or promoted) into another section or another Week column lights that section and draws a thin accent line at the exact slot the card will take between the cards already there. Reordering inside the same list keeps the cards-shift-apart gap instead of a line.
- **Task clipboard and active date.** Shared task menus and `Ctrl+C`/`Ctrl+X`/`Ctrl+V` copy, cut, and paste focused or selected tasks. Copy duplicates to the active date; cut moves while preserving status and clears only after success. Paste uses an ephemeral active date shared by Planner and Calendar (Today always targets today). Failed pastes retain the clipboard for retry.
- **Markdown task-ID markers are fully protected.** The hidden `^id` markers can no longer be reached or damaged by editing: a transaction filter blocks any edit that touches a marker unless the whole line is deleted (so deleting a task still works), `End` stops before the marker on marker lines, and `Enter` inserts the new task line below the full line so the id never migrates onto an empty task. A space typed at the end of a marker line stays visible (the hidden region is anchored to the exact two-space `  ^id` suffix `serializeTasks` emits).
- **Markdown Copy button + Ctrl+C.** An M3 split-button copies the document in the format its label shows — "Copy · Plain text" (titles only), "With details" (full metadata), or "JSON" (structured, no internal ids) — with the caret menu switching the persisted format. Copy respects the active Hide checked / Today only filters: what you see is what you copy. `Ctrl+C`/`Ctrl+X` inside the editor strip `^id` markers from the selection; no copy path ever emits task ids.
- **Markdown typeahead is state-driven.** Token suggestions (`@` dates, `#` projects, `!` priorities, `~` durations, `$` statuses) are detected from document state, so they fire on typing, paste, and caret re-entry, and switch when you change trigger. The menu opens at the caret (flips above near the bottom edge, clamps at viewport edges), `Up/Down` select, `Enter`/`Tab` accept, `Escape` dismisses. Hidden lines (filters) collapse via block decorations, so gutter line numbers show honest gaps instead of overlapping.
- **Markdown Mode has full keyboard navigation.** The toolbar (Save, Copy split-button, Scroll-to-now split-button) and the editor share one roving-focus panel: opening the mode auto-highlights the editor (not Save), `Up`/`Down` walk the toolbar stops, `Enter` on the editor hands focus to CodeMirror, and `Escape` steps back to navigating the toolbar — it never closes the mode (`Shift+C` still cycles modes). Split buttons support `ArrowLeft`/`ArrowRight` between primary action and chevron; both split-button dropdowns use `Enter` (opens with first item highlighted), `ArrowUp`/`ArrowDown` (cycle items), and `Escape` (closes and refocuses chevron).
- **Markdown uses Quick Add metadata parsing.** Markdown keeps headings, checkbox state, hidden IDs, subtasks, and validation, while each task body delegates token parsing to `parseQuickAdd`. Headingless lines default to Today and may use inline NLP dates; a valid heading controls its tasks' date. Subtasks now appear indented under their parent in the markdown itself — keeping their own time, priority, duration, and project — instead of only unscheduled ones nesting while scheduled ones flattened out to a bare line. Matching back to the right subtask on save is now id-based, not title-based, so a renamed subtask reconciles correctly. Pasted text is parsed live and only persisted after Save confirmation.
- **Task Detail Sheet footer toggles complete/incomplete, in both directions.** Clicking "Complete Task" on an open task keeps the sheet open and the button flips to "Mark as incomplete" (outline style, undo icon), which calls `uncompleteTask` and also keeps the sheet open — neither direction closes it anymore. Close with Esc or by navigating elsewhere; mirrors the existing `D`-key handler.
- **Project picker can create a project inline.** The project picker's dropdown has a "Create new project" row; it opens `CreateProjectModal`, and a new ephemeral `onProjectCreated` callback in `uiStore` hands the freshly created project's id back to the picker so it's assigned to the open task immediately.
- **Planner scroll position persists.** The Today planner mirrors the calendar's rAF-coalesced localStorage pattern (`kairo.planner.today.scrollTop`), restoring the scroll position after the live-query data resolves.
- **Tasks without a time get their own "Unscheduled" section** at the top of the planner, above Morning/Afternoon/Evening — they used to be mixed into Morning.
- **Priority no longer tints an unscheduled task's title text.** Its title now always reads in the
  standard text colour. On a card with no project colour, priority is still visible via the card's
  background tint and left border — there is no separate priority pill on this surface, that
  tint/border was always the signal, it just used to also duplicate onto the title text. On a card
  that *does* have a project colour, the project's inline tint and left border already overrode
  both, so priority now has no visual signal on those cards at all.
- **Sections and cards collapse, and it sticks.** Each section (Unscheduled/Morning/Afternoon/Evening) has a chevron to collapse/expand; a task card's expanded/collapsed subtask state does too. Both are stored in `uiStore` (`collapsedSectionKeys`, `expandedSubtaskIds`) behind zustand's `persist` middleware, so they survive reloads and stay in sync between Today and Week.
- **Collapse all / Expand all.** A single dropdown button in the planner header lists Expand all sections, Collapse all sections, Expand all cards, and Collapse all cards; right-clicking empty planner space (not a task card) opens the same four actions in a right-click menu.
- **Subtasks now render in their parent's project colour.** A subtask chip picks up the same colour tint as its parent task card instead of a flat neutral shade, so a project's colour carries down through its subtasks.
- **Task detail status/priority use the shared Select.** Status and priority no longer use
  native OS dropdowns; both render the local M3-style `Select` so the surface, menu, focus,
  and nested-popover behavior match the rest of Kyrou. The trigger surface is constant; value
  color appears only as a small dot beside the label.

## Keyboard navigation & select mode

- **Mouseless task nav.** With the planner focused, `Up`/`Down` move a focus ring across task
  cards (auto-scrolling into view), `Enter` opens the focused task's detail sheet, and
  `Left`/`Right` collapse/expand its subtasks. Arrow keys are ignored while typing or while a
  modal/detail overlay is open. Focus/expansion state lives in `uiStore`
  (`focusedTaskId`, `expandedSubtaskIds`) and the logic is in `usePlannerKeyboardNav.ts`. In
  select mode (see below), `Enter` toggles the focused card's selection instead of opening
  its detail sheet.
- **Up/Down step into expanded subtasks too.** If a task card is expanded, `Up`/`Down` walk
  through its visible subtask chips before moving to the next card. `Enter` on a subtask opens
  its own detail sheet (with a `↳ Parent` link back); `Left` on a subtask collapses the parent
  card and moves focus back onto it; `Right` on a subtask does nothing (a subtask has no
  children of its own). Reordering with `Ctrl+Shift+Up/Down` still only applies to top-level
  tasks.
- **`D` toggles done** on whatever task is currently highlighted — no need to open the detail
  sheet first. It works in the Today planner, the Week planner and the Calendar, on subtasks as
  well as top-level tasks, and it is rebindable in Settings → Keyboard. Toggling a subtask
  updates its parent the same way ticking its checkbox does: a parent whose last child you
  complete becomes done, and un-ticking a child reopens a done parent. If the Task Detail Sheet
  is open, `D` toggles that task; in select mode it toggles every selected task at once. It
  never fires while you're typing, and another dialog on top takes priority.
- **Context Menu key.** Pressing the physical Context Menu key with a focused task opens that
  card's normal shared menu beside the card, anchored to that card's position (the OS reports no
  cursor coordinates for this key); it is the same event path as a right-click. Task rows carry
  `tabIndex={0}` so the key can target them at all. It works on a focused **subtask** too,
  opening that subtask's own menu. With nothing focused it does nothing — the plain key is
  strictly the task menu.
- **`Shift` + Context Menu key** opens the expand/collapse menu instead — the same four actions
  as right-clicking empty planner space, navigable with the arrow keys and `Enter`. The plain
  Context Menu key used to open *both* menus at once; it now only ever opens the task's.
- **Context menu fully captures keyboard while open.** The menu marks itself `data-focus-stop`, so
  `usePlannerKeyboardNav`'s window-level listener yields to it — Enter/arrow keys no longer leak
  through to the planner and open the underlying task's detail sheet or move planner focus while
  a menu is open.
- **Touch swipe quick actions.** On touch devices, swiping a task right-to-left opens the same
  shared context menu regardless of done state. Swiping left-to-right on an open task previews the
  secondary token before completing it; swiping left-to-right on an already-done task uses the
  full-opacity `success`/`success-container` treatment before restoring it to not-done. This is
  intentionally only a quick-action layer; desktop HTML5 drag/click is unchanged and remains the
  reorder/schedule path until full touch DnD gets its own pass.
- **`Shift+N` scrolls to Now**, configurable in Settings → Keyboard, in both Calendar mode and the
  planner list. In the Today planner it focuses/scrolls to the first task at or after the current
  time, falling back to whichever of Morning/Afternoon/Evening currently holds "now" if nothing
  qualifies. In Calendar mode it's the same behavior as clicking the **Now** button, whose hover
  title shows the hint. See [Week](/features/week) for the planner's column-scrolling variant and
  [Calendar](/features/calendar) for the calendar's own `Up`/`Down`/`Enter`/`PageUp`/`PageDown`
  keyboard navigation over scheduled blocks.
  Because it sets focus, not just scroll position, `Up`/`Down`/`Enter` keep working immediately
  after — they continue from the task `Shift+N` landed on instead of wherever focus happened to
  be before.
- **Quick Add close hands focus back immediately.** Closing Quick Add no longer leaves a stale
  focus target behind — arrow-key planner navigation works on the very next keypress instead of
  needing an extra click first.
- **Two-mode focus inside modals and the Task Detail Sheet.** These overlays open in **navigate**
  mode — Up/Down/Home/End move a highlight between fields (Left/Right move within the duration
  presets), nothing is being edited yet. Enter drops into **edit** mode and hands real focus to
  that field; every other key belongs to it from there. Escape steps back one rung at a time —
  edit -> navigate -> close the overlay — so leaving a field never also closes the sheet in the
  same keypress. Opening the sheet no longer autofocuses the title; it's highlighted, not edited,
  until you press Enter on it. The Backlog sidebar gets the same Up/Down navigation but is
  deliberately not Tab-trapped, since it's meant to coexist with the rest of the page rather than
  behave like a modal.
- **Backlog sidebar has the same keyboard shortcuts as a task card.** `D` marks the highlighted
  backlog task done/not done, `Enter` opens it in the detail sheet, and the Context Menu key
  opens that task's own menu — instead of the browser's native right-click menu.
- **Task menu keyboard nav.** The right-click/Context-Menu-key menu follows the standard menu
  keyboard pattern: Up/Down move the highlight, Right opens a flyout (Left closes it), Home/End
  jump to the ends, Escape closes an open flyout before the whole menu. Every task menu now leads
  with a "Mark as done" / "Mark as not done" toggle above the usual actions — it flips every
  selected task in the same direction (any outstanding task in the selection marks all done; all
  done marks all outstanding).
- **Defer flyout is a vertical list.** The context menu's Defer action opens a vertical input flyout (instead of a chip grid). An input field sits at the top for typing custom time offsets (e.g. "45m", "1h30m", "-30m", matching the duration field grammar); below it are preset buttons (+15m, +30m, +1h, −15m, −30m, −1h). Navigation: ↑/↓ highlight presets, Enter applies, type and Enter for a custom offset. A preview shows the resulting time at the bottom.
- **Select mode.** A `checklist` toggle in the planner header (Today + Week) or `Shift+M`
  turns on multi-select: task checkboxes become selection controls, tapping a card selects it
  (instead of opening detail or toggling done), and right-clicking runs bulk context-menu
  actions across the whole selection. Selected cards get a blue glow and lift slightly (`ring-2
  ring-secondary` + shadow + a small upward translate) so selection is visible at a glance —
  the checkbox itself still toggles done, unchanged. Turning select mode off clears the
  selection. This replaces the old right-click-drag multi-select. Selection is task-level;
  subtask-level selection is a deferred follow-up.
- **Dismissal.** All modals, the detail sheet, sidebars, and popovers are coordinated by a
  central overlay layer: opening a modal closes others, and `Esc` closes the topmost overlay
  first — so a picker popover inside the Task Detail Sheet closes on the first `Esc`, and the
  sheet itself closes on the second.

## Where to start editing

- Changing what a task card shows -> `TaskCard.tsx`.
- Changing planner layout/sections -> `PlannerView.tsx` + `TaskSection.tsx`.
- Changing markdown syntax/behavior -> `MarkdownEditor.tsx`, `taskMarkdown.ts`, `markdownSave.ts`.
- Adding a new task action (e.g. a context-menu item) -> `src/components/ui/contextMenuItems.tsx`.
