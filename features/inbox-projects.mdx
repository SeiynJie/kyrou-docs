## What it does

The Inbox & Projects screen (`/inbox`) is where undated/backlog tasks and project management live together: a sortable list of tasks not yet scheduled to a date, grouped and organized by project, plus the ability to create/edit projects (name, color, emoji).

## Files tied to it

| File | Purpose |
|---|---|
| `src/features/inbox/InboxProjectsPage.tsx` | Route target for `/inbox`; top-level page composing the sections below |
| `src/features/inbox/components/CollapsibleSection.tsx` | Expand/collapse wrapper used to group tasks (e.g. per project) |
| `src/features/inbox/components/CreateProjectModal.tsx` | Modal for creating/editing a project; mounted globally in `App.tsx` so it can be opened from anywhere |
| `src/features/inbox/components/InboxTaskRow.tsx` | A single task row in the inbox list |
| `src/features/inbox/components/InlineInput.tsx` | Inline text input used for quick renaming/adding without a modal |
| `src/features/inbox/components/SortMenu.tsx` | Sort-order picker for the inbox list |

## Key concepts / how it connects

- **`src/features/projects/components/` exists but is currently empty.** Despite the folder scaffold, all project-related UI logic actually lives under `src/features/inbox/components/` today (`CreateProjectModal.tsx` etc.) — don't go looking in `projects/` for working code.
- **Project CRUD goes through `src/db/repositories/projectRepository.ts`**, following the same repository pattern as tasks — never import Dexie directly from a component.
- **Project shape**: `{ id, name, color, emoji?, createdAt, updatedAt }` (`src/types/task.ts`). Color is a hex string; emoji is optional (added in Dexie schema `version(2)`, see `src/db/index.ts`).
- **A task's `projectId: number | null`** links it to a project; the inbox groups/filters using that field.
- **`InboxTaskRow`'s right-click menu is the same shared `buildTaskMenu()`** used by the planner's
  `TaskCard` and `TimeBlock` — it previously hand-rolled a near-copy, which has been removed. That
  means it gets the same keyboard nav (arrow keys, flyouts, Home/End, Escape) and the top-level
  "Mark as done"/"Mark as not done" toggle for free; see [Today](/features/today) for the keyboard
  details.
- **`InboxTaskRow.tsx` currently has no production call site** — `InboxProjectsPage` renders
  `TaskCard` for every row instead. It's a candidate for deletion, left in place for now.
- **The page is keyboard-navigable via the shared roving-focus panel**, the same primitive used by
  Settings and the Task Detail Sheet. `CollapsibleSection` headers are a `FocusStop` group
  (`group="horizontal"`: Left collapses, Right expands), and the `TaskCard`s inside each section
  are `FocusStop`s too. `CollapsibleSection` moved off native `<details>`/`<summary>` onto a
  controlled `open` state with `hidden="until-found"` on the collapsed body, specifically to keep
  Ctrl+F find-in-page working inside a collapsed section while still being roving-nav-addressable;
  the header toggle is a real `<button>` so Enter/Space stay native.
- **The Backlog sidebar now renders on this page too**, reusing `uiStore.backlogOpen` — no new
  state was added for it.
- **A project can be marked "Default project"** — a toggle in `CreateProjectModal` when editing an
  existing project, backed by `isDefault` on `Project` and `setDefaultProject()` in
  `projectRepository.ts` (only one project can be default at a time; setting one clears the rest).
  Quick Add assigns new tasks to the default project when no `#project` token is typed — see
  [Quick Add](/features/quick-add).
- Per-row action buttons are reachable via Tab but are not yet in a horizontal roving group —
  deferred, not yet Left/Right navigable like the rest of the page.

## Where to start editing

- Changing the inbox list/sort behavior -> `InboxProjectsPage.tsx` + `SortMenu.tsx`.
- Changing project creation/edit fields -> `CreateProjectModal.tsx` (and `projectRepository.ts` if you add a field — see [Editing -> Features](/editing/features)).
- Changing a single row's look -> `InboxTaskRow.tsx`.
