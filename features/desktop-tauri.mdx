## What it does

Kyrou ships as a Windows desktop app by wrapping the same web build in Tauri — a Rust shell that loads the Vite production build (`dist/`) into a native window, adds OS integration (tray/minimize, global hotkey, autostart, auto-update), and packages it as an NSIS installer.

## Files tied to it

| File | Purpose |
|---|---|
| `src-tauri/tauri.conf.json` | Main Tauri config: product name, version, window size, bundle targets, updater endpoint + pubkey |
| `src-tauri/src/main.rs` / `src-tauri/src/lib.rs` | Rust entry point and app setup (tray, plugins, commands like `set_minimize_to_tray`) |
| `src/features/settings/lib/updater.ts` | Frontend side of auto-update — see [Settings & Updates](/features/settings-updates) |
| `src/features/settings/lib/globalHotkey.ts` | Registers the OS-level "open Kyrou" hotkey |

## Key facts (from `src-tauri/tauri.conf.json`)

- **Product name**: Kyrou · **identifier**: `app.kyrou.desktop` · **version**: kept in sync with `package.json`-style semver (currently `0.1.2`)
- **Frontend source**: `../dist` (the Vite production build) — `beforeBuildCommand` runs `npm run build` automatically
- **Bundle target**: `nsis` only (Windows installer) — `createUpdaterArtifacts: true` so each build also emits the signed update manifest
- **Window**: 1200x800, resizable, `dragDropEnabled: false`, frameless (`decorations:false`)
- **Custom title bar**: native Minimize / Maximize-Restore / Close controls (Windows), drag region on title bar and sidebar logo row, double-click toggles maximize
- **Updater endpoint**: `https://github.com/SeiynJie/kyrou-releases/releases/latest/download/latest.json` (a public releases-only repo — the source repo is private), verified against an embedded minisign public key baked into the config

Plugins used: `autostart`, `global-shortcut`, `process`, `updater` (see the `@tauri-apps/plugin-*` entries in `package.json`).

## Key concepts / how it connects

- **HashRouter, not BrowserRouter.** `src/App.tsx` uses `HashRouter` specifically because the desktop build loads from a `file://` path, where path-based routing can't resolve. If you ever see routing break only in the desktop build, this is the first thing to check.
- **`isDesktop()`** (`src/features/settings/lib/updater.ts`) is the single check used everywhere to branch desktop-only behavior (`'__TAURI_INTERNALS__' in window`).
- **Auto-update is two-sided**: the frontend (`updater.ts`) calls the Tauri updater plugin to check/download/install; the *publishing* side is the release pipeline (see [Release](/release)) which must produce a signed `latest.json` matching the pubkey in `tauri.conf.json` for update checks to succeed.
- **Local dev vs desktop dev**: `npm run dev` runs the plain Vite web app. `npm run app:dev` launches the Tauri shell with `src-tauri/tauri.dev.conf.json`, a separate `Kyrou Development` app using identifier `app.kairo.desktop.dev` and the `kyrou-dev` deep-link scheme. Development and e2e use separate AppData (including `auth-session.json`) and a separate single-instance identity, so they can run alongside the installed production app (`app.kairo.desktop` / `kyrou`) without sharing its login or window. Build the e2e binary with `npm run app:build:test`.
- **Tray & global hotkey**: left-clicking the tray icon shows/focuses the window (the tray menu still has Show/Quit). The `Ctrl+Shift+X` global hotkey is a *toggle* with focus-first semantics — hidden/unfocused → show + focus; already focused → hide to tray (`globalHotkey.ts`).

  The hotkey is owned **exclusively** by the OS-level registration in `globalHotkey.ts`. It must never also exist as an in-app DOM action in `useKeyboardShortcuts` — it did until 2026-07-16, and the two handlers cancelled each other out whenever the window was focused, which is why the shortcut appeared dead on a fresh launch until you closed the window once. Note `detectShortcutConflicts.ts` cannot catch this: it only finds duplicate binds *within the app's own map*, and is blind to a bind claimed by both the DOM layer and the OS layer. If registration fails (usually another app already owns the accelerator), a toast now says so and points at Settings → Keyboard — without it the failure is invisible, since a release build has no devtools console and `plugin-log` is not a JS dependency.
- **Minimize-to-tray needs BOTH sides to agree, and the JS side wins.** "Minimize to tray on close" only works if two independent things line up. (1) Rust's `MinimizeToTray` state (`lib.rs`) boots at `false` and is only ever set by the frontend's `invoke('set_minimize_to_tray', ...)`; that sync must be driven by a *subscribed* store value (`useSettingsStore((s) => s.minimizeToTray)` with the value in the effect deps), not a one-shot `getState()` read at mount, which can fire before zustand's `persist` rehydration lands and pin Rust at `false` for the whole session. (2) Any JS `onCloseRequested` listener **must call `event.preventDefault()`** when the setting is on: Tauri's wrapper in `@tauri-apps/api/window` calls `this.destroy()` after your handler unless you prevent it, which destroys the window even though Rust already called `api.prevent_close()` and hid it. Both bugs existed together until 2026-08-12; the second one presents as "window hides to tray, then the app quits a moment later."
- **Logging**: `tauri_plugin_log` writes an Info-level log file to the OS app-log directory in **all** builds (release included) — check it when tray/shortcut/updater behavior misfires in the field; dev builds also log to stdout.

## HUD overlay

The HUD is an always-on-top floating card showing what you should focus on right now, visible even when Kyrou's main window is hidden or behind other applications. It dims when unfocused (default 35% opacity) and brightens on hover.

### What it shows

- **Current objective:** the task or routine step you're actively working on, with time remaining
- **Progress:** routine step count (e.g. "2 of 6"), or elapsed time on a task
- **Schedule changes:** if the current block is ending soon (≤5 min), past end ("schedule drift" at 5–15 min, "overdue" in red at 15+ min), or just completed
- **Lookahead:** next block and when it starts (in 8 minutes, starts in 2 min, etc.)

### Modes

- **Micro:** one line only (title + time)
- **Compact:** header + footer hint (works well while focused)
- **Expanded:** full view with all details (a persisted mode set via M key or in Settings → General → HUD overlay; also auto-activates for decision views or high-priority states)

You can cycle modes with the **M** key (Micro → Compact → Expanded → Micro) or select your preferred mode in Settings → General → HUD overlay — the choice persists. This works in every state, including the idle card you get when nothing is scheduled or the day is over.

### Getting to it

1. **Settings switch:** Settings → General → HUD overlay → toggle on (also starts at boot if enabled)
2. **Tray menu:** Right-click the Kyrou tray icon → "Toggle HUD"
3. **Hotkey:** **Ctrl+Alt+H** cycles through hidden → focused → off (dismissing this way turns the HUD off — the Settings switch and tray item flip with it — rather than just returning focus to the previous app)

### Keyboard

- **Ctrl+Alt+H:** hidden → show + focus; unfocused → focus; focused → turns the HUD off (flips the persisted HUD switch, staying in sync with Settings and the tray)
- **Esc:** rest (dim, plate stays on screen)
- **Arrow keys:** walk actions (Complete, Start, Done step, Open in Kyrou)
- **Enter** or **D:** run the highlighted action
- **Shift+F:** run Open in Kyrou
- **M:** flip mode

### Actions

- **Complete:** mark the current task done and return focus to the main window
- **Start:** begin a routine (only for routines with no active session)
- **Done step:** mark the current routine step done and move to the next
- **Open in Kyrou (Shift+F):** show and focus the main Kyrou window, then land the keyboard on the block the card was naming — the same find as the app's own Shift+F, so a timeboxed task goes to its block in the timebox rail (opening the rail if it is closed) and anything else to its planner row. Another page switches to Today first, and another day travels back to today first. Cards that name no block (Free window, the completion flash) only lift the window.

### Appearance

- **Skins:** Quest (warm, glitchy alert style) or Minimal (clean, cool) — pick in Settings
- **Dim opacity:** draggable slider under the skin picker (15%–100%, default 35%); hover always raises to 100%
- **Position:** drag the card anywhere on it (except its action buttons) and it snaps to screen edges — drop within 64 pixels of the edge and it rests flush against that edge. Both left-right and up-down snap independently, so a drop near the right edge but vertically centred snaps only horizontally. The position is remembered and always kept inside the monitor's usable area (above the taskbar), even if you unplug a monitor or change resolution. On mode change (M key or Settings), the edge it's docked to stays frozen: a right-docked HUD grows leftward into the screen, a left-docked HUD grows rightward

### How it knows what you're doing

The HUD reads your schedule from the main Kyrou window without needing to reload — it syncs across windows using the browser's `storage` event. When you complete a task in the HUD, the main window instantly sees it; when you start a routine in the main app, the HUD immediately shows it.

## Where to start editing

- Window size/behavior, bundle targets, updater endpoint -> `src-tauri/tauri.conf.json`.
- Native OS integration (tray, custom commands invoked from the frontend via `invoke(...)`) -> `src-tauri/src/lib.rs`.
- Frontend update-check UX -> `src/features/settings/lib/updater.ts` and `UpdatesPage.tsx`.
- HUD overlay window bootstrap and hotkey -> `src/tauri/hud.ts`; view engine -> `src/kyrou/hud.ts`; presentation -> `src/app/Hud.tsx`.
- Cutting an actual signed release -> [Release](/release).
