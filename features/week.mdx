## What it does

The Week screen (`/week`) shows seven days side by side, in either a planner-list layout or the shared time-grid calendar (see [Calendar](/features/calendar)) — same Planner/Calendar/Markdown mode-switching concept as Today, just scoped to a week instead of a single day.

## Files tied to it

| File | Purpose |
|---|---|
| `src/features/week/components/WeekPage.tsx` | Route target for `/week`; orchestrates the week view similarly to `TodayPage` |
| `src/features/week/components/WeekPlannerView.tsx` | List-based planner laid out across seven day columns |
| `src/features/week/components/WeekColumn.tsx` | A single day's column within the planner layout |
| `src/features/week/components/WeekHeader.tsx` | Date-range header / day labels + navigation (prev/next week) |

Calendar mode within Week reuses `src/features/calendar/UnifiedCalendar.tsx` with `mode="week"` — there is no separate week-specific calendar grid implementation.

## Key concepts / how it connects

- **Reuses Today's building blocks where possible.** Week's planner columns are conceptually the same task cards/sections as Today's `PlannerView`, just tiled across 7 dates instead of 1.
- **Reuses Today's subtask surface too.** Week planner columns render subtasks through the same `TaskCard` as Today, so context-menu actions, click/Enter editing, and the promote/demote actions all stay identical across both pages.
- **Data comes from `useTasksForRange(startDate, endDate)`** in `src/db/repositories/taskRepository.ts`, which returns a flat array of tasks across the visible date range; the Week components bucket that array by date client-side.
- **View-switching (`Shift+V`)** cycles between `/today`, `/week`, and `/inbox` — wired in `GlobalShortcuts` in `src/App.tsx`.
- **Select mode & keyboard nav.** The planner-header `checklist` toggle (or `Shift+M`) turns on multi-select here too. Keyboard task navigation is per-column: `Up`/`Down` move within the active column (auto-scrolling), and `Alt+Left` / `Alt+Right` move between columns, landing on the same row (clamped to the target column's length) and scrolling it into view — extending the loaded date window if you step past its edge. Those keys, and any click or right-click in a column, update the shared active date. `Tab` is intentionally left alone for native browser focus order; it is not repurposed for column navigation. `Ctrl+C`/`Ctrl+X`/`Ctrl+V` and the task-menu Cut/Copy/Paste rows use that active week-column date; copy duplicates and cut preserves status when moving. See [Today → Keyboard navigation & select mode](/features/today) for the rest of the shared behavior.
- **Week calendar blocks stay independent.** Since a scheduled subtask is a real task row, the shared calendar view renders it as its own block (`↳ title`) alongside its parent — moving/resizing one never touches the other.
- **Quick Add prefills the focused column's date.** Opening Quick Add from the Week planner seeds the currently-focused column's date as a parsed chip (precedence: an explicit prefill wins over a draft, which wins over this contextual default — `src/lib/weekPlannerPrefill.ts`). Each `WeekColumn` header also has an Add-task icon button (shown on hover/active) that opens Quick Add pre-filled with that column's date directly, with no need to focus it first.
- **Week planner scroll position persists** as a fractional day-offset relative to today (`kairo.planner.week.dayOffset`, `src/lib/weekScroll.ts`) — zoom- and window-size-independent — falling back to `scrollToToday()` if nothing is saved yet.
- **Scheduled subtasks are blocks in the week planner list too.** `WeekPlannerView` buckets every dated task with `parentId` set into its day column same as any task, so a scheduled subtask shows as its own block. Dropping a subtask onto a day column sets its date (preserving its own start time) via the ordinary task-update path.
- **Each column gets its own "Unscheduled" section** at the top, above Morning/Afternoon/Evening, for tasks without a time — same change as Today, applied per column.
- **Sections and cards collapse, and it persists.** Every column's sections have a collapse chevron; a card's expanded/collapsed subtask state does too. Both live in `uiStore` behind zustand's `persist` middleware, so state is shared with Today and survives reloads.
- **Collapse all / Expand all** is one header dropdown (Expand/Collapse all sections, Expand/Collapse all cards) acting on every visible card across all columns; right-clicking empty planner space opens the same four actions in a right-click menu — same source as Today.
- **Subtask keyboard nav works here too.** `Up`/`Down` step into an expanded card's subtask chips before moving to the next card in the column, same as Today — see [Today → Keyboard navigation & select mode](/features/today).
- **`D` toggles done on the highlighted task** here as well, subtasks included, without opening the detail sheet — see [Today](/features/today).
- **`Shift+N` scrolls to Now here too**, scrolling to today's column in the week planner and also selecting it as the active column with a focused task, so `Up`/`Down`/`Alt+Left`/`Alt+Right` continue from there (Calendar mode keeps its own Now-button behavior — see [Calendar](/features/calendar)).

## Where to start editing

- Changing the week layout/columns -> `WeekPlannerView.tsx` + `WeekColumn.tsx`.
- Changing the date-range header or week navigation -> `WeekHeader.tsx`.
- Changing calendar-mode behavior for the week -> see [Calendar](/features/calendar) (shared component).
