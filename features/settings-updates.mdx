## What it does

The Settings modal is a tabbed dialog (General, Appearance, Import & Export, Keyboard, Dev, Pricing, Updates) covering app preferences, theme, backup export/import, keyboard-shortcut rebinding, developer/seed tools, and — on the desktop build — checking for and installing app updates.

On mobile, Settings is reachable from the bottom navigation as a real tab-bar action. It opens this same Settings modal and does not navigate away from the current Today/Week/Inbox view.

## Files tied to it

| File | Purpose |
|---|---|
| `src/app/SettingsModal.tsx` | The modal class component — tab switching and layout for preferences, appearance, import/export, keyboard, dev tools, pricing, updates |
| `src/tauri/updater.ts` | Tauri auto-update logic — `isDesktop()`, `checkForUpdate()`, `getAppVersion()` |
| `src/tauri/globalHotkey.ts` | Registers the global "open Kyrou" OS-level hotkey via the Tauri global-shortcut plugin |

## Key concepts / how it connects

- **`isDesktop()`** (in `src/tauri/platform.ts`) checks for `'__TAURI_INTERNALS__' in window` — this is the standard way the whole codebase distinguishes "running as a Tauri desktop app" from "running as a plain web build." Update checks, the global hotkey, and tray behavior all no-op in the browser.
- **Update flow**: `src/tauri/updater.ts` calls the Tauri updater plugin's `check()`, which hits the endpoint in `src-tauri/tauri.conf.json` (`https://github.com/SeiynJie/kyrou-releases/releases/latest/download/latest.json`). If a newer version exists, it shows a toast with an "Update" button that calls `downloadAndInstall()` then relaunches the app. See [Desktop (Tauri)](/features/desktop-tauri) for the release-side half of this.
- **Startup update check** is orchestrated in `App.tsx`, not inside the settings feature: on first launch it asks the user via a toast whether to check on startup, and persists the answer to `settingsStore` (`updateCheckOnStartup`).
- **Planner automation** lives in Appearance: an "Auto-collapse empty and completed sections" toggle
  (with an info icon spelling out the rule) folds a planner section only once it is empty or every
  task in it — including nested subtasks, not just the top-level row — is done, and reopens it on
  its own the moment unfinished work lands there; a second toggle completes a parent when every
  subtask is done.
- **Global hotkey registration is serialized** (`globalHotkey.ts` keeps a `lock` promise chain) specifically to survive React StrictMode's double-invoke of effects in dev, which would otherwise try to register the same OS-level accelerator twice.
- Shortcut bindings themselves live in `src/stores/settingsStore.ts` (persisted) and are consumed by `useKeyboardShortcuts` in `App.tsx`; conflict detection is `src/lib/detectShortcutConflicts.ts`.
- **The page switcher and every settings row are keyboard-navigable via the shared roving-focus panel** (`src/lib/hooks/useRovingPanel.ts`, already wired on `Modal`). The tab strip is a `FocusStop` group with `group="horizontal"` — Left/Right switch pages, Up/Down walk down the current page's rows (`Toggle`, `KeyboardShortcutRow`, and the rows in `AppearancePage`/`UpdatesPage`/`DevPage`). Enter hands real focus to a row's control; Escape steps back out before closing the modal.

<Note>Because `Modal` is not portaled, a nested dialog opened from inside Settings (`KeypressCapture`, while rebinding a shortcut) renders inside Settings' own DOM container. `useRovingPanel` explicitly ignores keys that originate inside a nested `role="dialog"` so the outer Settings panel doesn't also try to interpret them as roving-nav input.</Note>

## Update required screen (desktop)

If Kyrou detects that the installed build is too old to keep supporting, it shows a full-screen "Update required" card in place of the normal app, with **Update now** (installs the latest version and relaunches) and **Export my data** (always enabled, even here). This is desktop-only, and it only appears when there's an update available that actually resolves it — a network hiccup or being offline never triggers it, and it never shows if the app has nothing newer to offer you. See [Desktop (Tauri) → Supported-version floor](/features/desktop-tauri#supported-version-floor) for the full picture.

## General → Privacy

The General tab includes a **Privacy** section at the bottom with:

- **Share anonymous usage data** toggle — Controls whether Kyrou sends usage events and session replay data to PostHog for analytics and debugging. ON by default. Turning it off calls PostHog's own `opt_out_capturing()` API, which stops both event capture and session replay; the choice is persisted by PostHog under `__ph_opt_in_out_<token>` in localStorage.
- **Sub-label** — "Helps improve Kyrou. No account or email is collected." Clarifies that only anonymous usage data is sent, not personal information.

Session replay is full-fidelity (all text visible in replays) — a deliberate choice to support debugging Kyrou's UI. Users who object can opt out via this toggle.

## General → HUD overlay (desktop)

The General tab includes a **HUD overlay** section (on desktop only) with:

- **Show HUD overlay** toggle — Turns the always-on-top card on/off. Persisted, so it remembers your choice on restart. Keyboard: Ctrl+Alt+H steps through hidden→focused→off, and flips this same toggle when it turns the HUD off.
- **Skin** segmented control — Quest (warm, alert aesthetic) or Minimal (clean, cool). Pick your visual style.
- **Rest mode** segmented control — Micro (one line only), Compact (header + footer), or Expanded (full view). This is the mode the HUD adopts, focused or not. Only two states override it: a decision prompt forces Expanded, and an alert or high-urgency block promotes Micro to Compact.
- **Unfocused opacity** range slider — How dim the card gets when you're not interacting with it (15%–100%, default 35%). Hover always brightens it to 100%.

All settings are persisted to the desktop settings store and take effect immediately. Ctrl+Alt+H cycles the HUD through hidden/focused/off, flipping the Show HUD overlay toggle above when it turns the HUD off; Esc instead drops to rest without hiding. While the HUD is focused, M cycles Micro to Compact to Expanded and saves the result here. See [Desktop (Tauri) → HUD overlay](/features/desktop-tauri#hud-overlay) for the full user guide.

## Sync & account

The Sync & account tab manages your sign-in state and local data:

- **When signed out:** Shows "Your data stays on this device and is not synced" and a **Sign in** button. When you click Sign in, your browser opens Google's login page. After you complete sign-in, Kyrou returns and shows your session.
- **When signed in:** Shows your email address (or name), a **Sign out** button, and your sync status. If you have items on this device from before you signed in, a **Bring local data into this account** button appears. Click it to move all your local items (tasks, projects, routines, logs, runs) into your account — they will move, not copy, so your device's local storage becomes empty. Clicking **Sign out** switches the planner and routines views straight away to whatever is stored on this device — your account's items are no longer shown — with no reload needed.
- **After moving local data:** The button disappears once the move completes. If you sign out and back in to the same or a different account, your local device stays empty (your moved items stay in the account you moved them to). If you have local items again after signing in and choose "Keep separate" on the move prompt, they stay on this device and don't sync.

The move is atomic — either it succeeds completely or your data stays untouched. A second browser profile won't show the move prompt if you've already declined it once (you'll need to clear your browser data to see it again).

## Where to start editing

- Adding a new settings tab -> add a `*Page.tsx` under `components/` and wire it into `SettingsModal.tsx`.
- Changing update-check behavior -> `updater.ts`.
- Changing/adding a keyboard shortcut -> `settingsStore.ts` (default bindings) + `KeyboardSection.tsx` (UI) + `detectShortcutConflicts.ts` (validation).
