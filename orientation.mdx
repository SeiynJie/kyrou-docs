Kyrou is a **local-first desktop/web daily planner**. There is no backend, no auth, and no
external API calls — everything lives in one `localStorage` record, in the browser or in the
Tauri desktop shell. On 2026-09-04 the entire UI and data layer were replaced by a **mechanical,
one-to-one port** of a hand-built Claude Design app: Dexie/IndexedDB, React Router, Tailwind CSS,
`@dnd-kit`, `chrono-node`, `react-toastify`, and the in-progress Supabase/Neon sync migration were
all removed. This page describes the app as it exists today.

## The stack

| Layer | Tech |
|---|---|
| UI framework | React 19 + Vite + TypeScript, class components (`extends Component<Props, any>`) |
| Styling | CSS custom-property tokens in `src/ds/tokens/*.css`, dark by default with Light/System support, no Tailwind |
| Persistence | One `localStorage` record (`kyrou:data:v1`) owned by `src/kyrou/store.ts` |
| Desktop settings | Zustand (`src/tauri/settingsStore.ts`) — three booleans, not domain data |
| Icons | `lucide` (`window.lucide.createIcons()`), not `lucide-react` |
| NLP quick-add parsing | The design's own parser, `src/kyrou/parse.ts` — no `chrono-node` |
| Desktop packaging | Tauri v2 (Rust shell, NSIS installer on Windows) |

## The `src/` map

```
src/
  main.tsx          entry point: fonts, tokens, lucide bootstrap, mounts <App/>
  App.tsx           the shell — no router, page state + kyrou:* window listeners
  global.d.ts       window flags (KYROU_GLIDING, sinks, ...), <kyrou-collapse>, *.png
  app/              29 ported pages/panels/modals/leaves (flat, PascalCase, one per design file)
  ds/               10 shared design-system components + CSS token files
  kyrou/            25 engine modules — store, recur, routines, projects, parse, undo, theme, ...
  tauri/            desktop-only: tray, autostart, updater, hotkey, backup, links, settingsStore
```

The `@/` path alias maps to `src/` (configured in `vite.config.ts` and `tsconfig.app.json`).
`design-import/kyrou-app/` (canonical) and `design-import/kyrou-ds/` (reference) are the extracted
Claude Design projects every ported file was translated from — read-only, excluded from build,
lint, and tests.

## Paging, not routing

There is **no router**. `src/App.tsx` switches between Today / Week / Inbox / [Routines](/features/routines) by local
component state, mirrored to `localStorage['kyrou:lastPage']` so the last page persists across a
restart. Global keyboard shortcuts (Shift+1..4, Shift+A for Quick Add, Ctrl+. for Settings) and
every `kyrou:*` window event listener live in `App.tsx`; Ctrl+Z/Ctrl+Y for undo/redo are a global
capture listener in `src/kyrou/undo.ts`. Pages
accept an `embedded?: boolean` prop — Week mounts a `Today` instance per day column with
`embedded={true}`.

## Theme

Dark is the default, not the only option. `src/kyrou/theme.ts` (`KyrouTheme.get/set/init`)
resolves the persisted `kyrou-theme` key (`'light' | 'dark' | 'system'`) and sets `data-theme` on
`<html>`; light tokens are the `:root[data-theme="light"]` override in
`src/ds/tokens/colors.css`. `index.html`'s inline first-paint script applies the persisted choice
before first render (no flash), and Settings → Appearance → Theme is the user-facing switch.

## Mocked and inert surfaces

Sidebar starts **signed-out** by default. Feedback, Sync & account, and About & pricing render
exactly as designed but are inert — their handlers are deliberate no-ops
(`// ponytail: Feedback/Sync/Pricing inert by decision`). `docs/design-behaviour-spec.html` is the
copied behaviour reference listing every wired vs. `NOT WIRED` surface.

## Out of scope today

- **Mobile layout.** The design is desktop/web-window shaped; there is no mobile breakpoint tree,
  bottom nav, or bottom sheets in the ported app.
- **Sync, accounts, Supabase/Neon, Stripe.** Fully removed. Any future sync work needs a fresh
  design against the localStorage store below — the old Dexie-first sync plan no longer applies.
- **Markdown editing mode.**

## The golden data-flow rule

There is exactly one path data takes, and it is **synchronous**, not a reactive query layer:

```
UI component method
   |  calls a store function directly
   v
src/kyrou/store.ts (KyrouStore) — mutates its in-memory `data` object
   |  writes the whole record as JSON
   v
localStorage['kyrou:data:v1']
   |  subscribed components re-render (subs[] callbacks + forceUpdate),
   |  or via a 'kyrou:*' CustomEvent on window
   v
component re-renders
```

`KyrouStore`'s shape:

```
{ version, seq, days: { 'YYYY-MM-DD': [task] }, inbox: [task],
  projects: [{ id, name, tone }], routines: [routine], routineLog: {}, routineRuns: [] }
```

A task's identity lives in its day bucket — moving a task's date means moving it between buckets.
Every save that actually changes the record pushes the previous snapshot onto an in-memory,
session-only undo stack (50 deep); saves within 700ms sharing a coalesce key fold into one undo
step. Undo/redo swap whole snapshots and fire `kyrou:restore`.

**There is no repository layer, no `useLiveQuery`, and no IndexedDB.** Components import
`src/kyrou/store.ts`'s named exports directly. The engine modules are a one-directional dependency
chain, not a cycle: `store.ts` imports `recur.ts` (which itself imports nothing); `routines.ts`
imports `store.ts`, `recur.ts`, and `undo.ts`; `projects.ts` imports `store.ts` — nothing imports
back into `routines.ts` or `projects.ts`.

**Ceiling, not a bug:** this is one localStorage record, not a database (see the `// ponytail:`
note at the top of `src/kyrou/store.ts`). If it nears the ~5 MB localStorage limit, the upgrade
path is a plugin-fs-backed file, not IndexedDB. There is deliberately no migration from any
pre-port Dexie data.

Zustand (`src/tauri/settingsStore.ts`) is unrelated to `KyrouStore` — it holds only three desktop
preferences (`startOnStartup`, `minimizeToTray`, `updateCheckOnStartup`), never domain data.

## Dates and times are strings, never `Date`

Persisted fields use plain strings, unchanged by the port:

- Dates: `'YYYY-MM-DD'` (e.g. `'2026-07-14'`)
- Times: `'HH:mm'` (e.g. `'09:30'`)

No `Date` objects are stored on a task. This sidesteps timezone bugs entirely.
