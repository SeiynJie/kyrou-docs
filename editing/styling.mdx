## What changed

The pre-port styling system (Tailwind v4 `@theme` tokens in `src/index.css`, `cn()` /
`tailwind-merge`, `src/components/ui/*`) was removed in the 2026-09-04 design port. There is no
Tailwind anymore. Styling now mirrors Seji's Claude Design app exactly: CSS custom-property tokens
plus verbatim component CSS files.

## The token system

Tokens live in `src/ds/tokens/*.css`, imported once globally by `src/main.tsx`:

| File | Purpose |
|---|---|
| `colors.css` | Every color custom property (`--ink-*` neutral ramp, `--sand-*` accent, `--azure-*`, `--label-*`, semantic aliases like `--bg-app`, `--text-primary`, `--accent`) |
| `typography.css` | Font-size/weight/line-height scales. `--fs-*` values are `rem` (pixel-identical at the default 16px root), so text scales with the user's OS/browser text-size setting; `--lh-*`/`--fw-*` and the spacing/radius tokens are unaffected and stay unitless/`px` — layout does not scale, only text does |
| `fonts.css` | `--font-display` / `--font-sans` (Space Grotesk) and `--font-mono` (JetBrains Mono), loaded from `@fontsource/*` packages — no Google Fonts `<link>` |
| `spacing.css` | Spacing scale |
| `effects.css` | Shadows and similar |
| `motion.css` | Durations/easings |
| `base.css` | Base element resets |

There is **no `@theme` block, no Tailwind utility classes, and no `tailwind-merge`.** Component
CSS is copied verbatim from the design (`design-import/kyrou-app/*.dc.html`'s `<style>` blocks) into
a sibling `.css` file per component under `src/app/`, imported by that component only. `src/ds/`
components ship their own shared CSS in `src/ds/styles.css`.

**Dark by default; Light and System are also supported.** `src/ds/tokens/colors.css` defines the
dark palette on `:root` and a `:root[data-theme="light"]` override for light mode.
`src/kyrou/theme.ts` (`KyrouTheme.get/set/init`) resolves the persisted `kyrou-theme` key
(`'light' | 'dark' | 'system'`, default `'dark'`) and sets `data-theme` on `<html>`; `'system'`
follows `prefers-color-scheme`. The Settings → Appearance → Theme `SegmentedControl`
(`src/app/SettingsModal.tsx`) is the user-facing control, and `index.html`'s inline first-paint
script applies the persisted theme before first render so there's no flash.

**Rule: never hardcode a color in a ported component.** If a value isn't in
`src/ds/tokens/*.css`, it isn't part of the current design system — check
`design-import/kyrou-app/` (canonical) or `design-import/kyrou-ds/` (reference; the app zip's
compiled `_ds_bundle.js` wins on any conflict) before inventing one.

**Rule: never write a literal px font-size.** Always a `--fs-*` token or a `--type-*` role. This
was enforced retroactively by converting the three remaining hardcoded px font-sizes in ported
code (`Routines.tsx` x2, `RunDetail.tsx`) to their matching `--fs-*` token.

**Rule: never restore a scroll position with a plain `el.scrollTop = v` assignment.**
`src/kyrou/kyrou-scroll.css` sets `scroll-behavior: smooth` on every element (`html, body, *`), so
that assignment doesn't jump — it queues an animation, and a reflow that clamps `scrollTop` back to
`0` in the same tick (e.g. briefly collapsing an element to `height: 'auto'` to measure it) wins that
race every time. Use `el.scrollTo({ top: v, behavior: 'instant' })` instead, which opts out of
smooth-scrolling per-call. This bit `NoteField.autosize()` and `NoteBubble`'s equivalent exactly:
measuring the note textarea un-overflowed the host panel, the browser clamped its scroll position to
0, and only the instant `scrollTo` restore reliably wins the race — a plain `scrollTop =` assignment
looked correct in the diff but silently threw the panel back to the top on every keystroke. Any
future code that restores a scroll position anywhere in the app is exposed to the same trap.

## Inline styles: the `css()` helper

The design's inline `style="a:b;c:{{ x }}px"` attributes became
`style={css('a:b;c:${x}px')}` via `src/kyrou/css.ts` (`css()` is the ported form of the design
runtime's `cssToObj`, including `--custom-property` values). This keeps the exact declaration
strings diffable against the source `.dc.html` file — it is not a general-purpose style utility,
just the mechanical translation of that one pattern.

```ts
// src/kyrou/css.ts usage, from a ported component
style={css(`width:${v.width}px;background:var(--accent)`)}
```

Strings containing `url(...)` or a `;` inside parentheses were moved to the component's `.css`
file instead, per the port's rulebook (R3).

## Design system components (`src/ds/`)

Ten shared components, written from `design-import/kyrou-ds/`'s JSX and then diffed against the
app zip's compiled `_ds_bundle.js` (the bundle wins on any difference):

`Badge`, `Button`, `Checkbox`, `IconButton`, `NavItem`, `ParsedChip`, `SegmentedControl`,
`StatusPill`, `Switch`, `TimeChip` — re-exported from `src/ds/index.ts`. They are plain function
components with default parameters (no `defaultProps`, which React 19 dropped for function
components), and no global registration (the design runtime's `x-import
component-from-global-scope="KyrouDesignSystem_....Button"` pattern is gone — pages `import {
Button } from '@/ds'` directly).

Three known prop drops versus the DS-zip reference (the bundle won, per the rule above), none ever
passed by any ported page so none have a visible effect: `Checkbox` lost its `tone` prop
(undisclosed — no in-file PORT-NOTE); `StatusPill` lost its `dot` prop (undisclosed — no in-file
PORT-NOTE); `NavItem` lost `tooltip`/`collapsed`/`shortcut` props (disclosed — see the
`PORT-NOTE` in `src/ds/NavItem.tsx`).

## Icons

**`lucide`**, not `lucide-react`. The design renders `<i data-lucide="icon-name">` markup and
calls a global icon-refresh function; the port keeps that exact pattern —
`window.lucide.createIcons()` (declared in `src/global.d.ts`, wired in `src/kyrou/lucide.ts`) is
called after any render that introduces new icon markup, matching the design's own rAF-debounced
refresh rather than importing per-icon React components.

## Class components, not hooks

Every `src/app/*.tsx` file is a `React.Component` class (`extends Component<Props, any>`), one
per `design-import/kyrou-app/*.dc.html` file, matching the design runtime's `class Component
extends DCLogic` shape one-to-one. There is no `StrictMode` (it would double-invoke
`componentDidMount` side effects the design never accounted for). `render()` reads
`const v: any = { ...this.props, ...this.renderVals() }`, mirroring the design template's
render-value merge.

## `<kyrou-collapse>`

The design's custom element (`customElements.define`, guarded by
`if (!customElements.get('kyrou-collapse'))`) is kept verbatim, ported in `src/kyrou/collapse.ts`
and typed as a JSX intrinsic in `src/global.d.ts`: `<kyrou-collapse open={v.x}>`.

## Where design authority lives now

`DESIGN.md` (repo root) points to the current sources of truth instead of restating them:
`design-import/kyrou-app/` (canonical), `design-import/kyrou-ds/` (reference), and
`src/ds/tokens/*.css` / `src/ds/*.tsx` (what's actually live in the app). `npm run design:lint`
checks `DESIGN.md`'s own frontmatter for internal consistency — that frontmatter is a historical
holdover from the pre-port Material 3 token set and does not describe the live tokens; do not use
its color values when styling a component.

## Where to start editing

- New color/spacing/token value -> `src/ds/tokens/*.css`, then check whether `DESIGN.md` needs a
  pointer update.
- A shared primitive's look (`Button`, `Switch`, `Checkbox`, ...) -> `src/ds/*.tsx` — diff any
  change against `design-import/kyrou-ds/` and the app zip's compiled bundle before shipping it.
- A specific page/panel/modal's markup or styling -> its file under `src/app/` and the sibling
  `.css` file; the source of truth is the matching `design-import/kyrou-app/*.dc.html`. Any
  deviation from that source needs a `// PORT-NOTE:` comment and a note in whatever review/report
  process is active for the change.
- New icon -> use its `data-lucide="..."` name from the design; `window.lucide.createIcons()` is
  already wired globally, no new import needed.
