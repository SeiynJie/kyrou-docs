## What it does

Quick Add is the fast-entry modal (opened globally via a keyboard shortcut) where you type a task in plain English and Kyrou parses out the date, time, duration, priority, project, tags, subtasks, and status from the text as you type — no separate fields to fill in.

## Current grammar (`src/kyrou/parse.ts` + `src/kyrou/duration.ts`)

| Form | Meaning | Examples |
|---|---|---|
| **Time** | Single time | `4pm`, `4:00pm`, `4p`, `1230`, `@1230` (bare digits need `@`); `noon`, `midnight`; `at 9` / `@9` |
| **Time range** | Start + duration | `9-10am`, `8am to 630pm`, `8-630pm` (smart meridiem: `8-6pm` → `8am-6pm`), `0800-1730`, `10:30am to 9am` (wraps past midnight); needs `@`, minutes, or am/pm on one side or reads as plain text |
| **Date (month-day)** | Specific date | `@sep 25 2027`, `@sep 25, 2027`, `@25 sep 2027`, `@sep 25th` |
| **Date (slash/ISO)** | Specific date | `@9/25`, `@9/25/2027`, `@2027-09-25` |
| **Date (relative)** | Offset from today | `in 3 days`, `in 2 weeks`, `in 1 month`; `next mon`, `next month` |
| **Date (context)** | Today offset | `today`, `tomorrow`, `tonight` (today evening), `this weekend` |
| **Section** | Time of day | `@morning`, `@afternoon`, `@evening`, `this morning`, `this afternoon`, `this evening`, `tonight` (today evening) — bare `morning`/`afternoon`/`evening` never parse, so "Morning Routine" keeps its title |
| **Duration** | Task length | `2h`, `1h 30m`, `45 minutes`, `for 2h`, `~2h` |
| **Priority** | Task urgency | `p1–p4`, `!1–!3`, `!!!` / `!!` / `!` (Todoist/Things shorthands) |
| **Project** | Task owner | `#ProjectName` |
| **Recurrence** | Repeat pattern | `every mon wed fri`, `every 2 weeks`, `every other day`, `every 15th`, `every weekend`, `yearly` |
| **Subtasks** | Child tasks | `-- task a / task b` |

Date chips show the year only when it isn't the current year. `KyrouParse.clock` (text →
minutes) and `KyrouParse.range` are exported so other engines (Task Detail, Routine Editor) parse
the same grammar.

## Target day

Quick Add always shows — and the created task always carries — a target day, even when nothing was
typed. `window.KyrouQuickAddDay` is a hook the currently-active page installs: Today (not embedded
in a Week column) answers with its own day; Week answers with the focused column's day, or today
when no column is focused; Inbox installs nothing, so its tasks stay undated unless a date is typed.
With no date chip typed, the modal shows an implied, unremovable chip (dimmed, no × to clear) naming
that default day, and the submitted patch carries that date.

This also fixes handler ownership for the create event: previously, opening Quick Add from Week with
no day column focused created nothing, because no mounted `Today` column was listening. Now Week
itself picks up the event when no column is focused, and writes the task straight into that day's
store record.

| File | Purpose |

| `src/features/quickadd/components/ParsingChips.tsx` | Renders the little chips showing what was parsed (date, time, priority, project, tags...) as you type |
| `src/features/quickadd/useTokenAutocomplete.ts` | Wraps the shared `useTypeahead` hook (`src/lib/hooks/`) to autocomplete `#project` and other tokens, plus a "Create project" suggestion when a `#name` doesn't match an existing project |
| `src/lib/nlpParser.ts` | The actual parser — `parseQuickAdd(input)` returns a `ParsedTask`. Uses `chrono-node` for date/time extraction and its own regex-based token parsing for everything else |

## Key concepts / how it connects

`parseQuickAdd` strips recognized tokens out of the input one pass at a time and returns what's left as the title. Recognized syntax:

| Token | Meaning | Example |
|---|---|---|
| `chrono-node` natural dates/times | date + startTime | `tomorrow 3pm`, `next mon 9am` |
| `#name` | project | `#phoenix` |
| `$status` | status (`todo`, `doing`, etc. map to `TaskStatus`) | `$doing` |
| `p1`/`p2`/`p3`/`high`/`med`/`low` style tokens | priority | `!high` (see `nlpParser.ts` for exact grammar) |
| `-- a / b / c` | subtasks: everything after `--`, split on `/` (commas are literal text) | `Plan trip -- book flights / pack` |

- **`durationExplicit`** on the returned `ParsedTask` distinguishes "user typed a duration" from "defaulted to 30 minutes" — used so the UI doesn't show a duration chip for a default it invented.
- **Autocomplete is layered on top of parsing, not part of it.** `useTokenAutocomplete` watches the raw input and the caret position to offer project-name completions; `nlpParser.ts` has no knowledge of the project list — it just extracts whatever string follows `#`.
- **No `#project` token falls back to the default project.** `resolveProjectId()` in `src/db/repositories/projectRepository.ts` assigns a task with no `#name` in its text to whichever project has `isDefault` set (see [Inbox & Projects](/features/inbox-projects)). Typing an explicit `#name` that doesn't match any project still resolves to unassigned (prompting the "Create project" suggestion) rather than falling back to the default.
- Submitting the modal calls the same task-repository create function used everywhere else (`src/db/repositories/taskRepository.ts`) — Quick Add is purely an input-parsing layer in front of the same data flow described in [Orientation](/orientation).
- **Successive entry is deliberate.** A successful creation removes the saved draft, clears the
  field, and returns focus to it while leaving Quick Add open for the next task. A failed create
  keeps the field and draft intact for retry. `Esc`, Cancel, the close button, and a backdrop
  click still dismiss the modal; `Shift+A` toggles it only when focus is not in a typing target.
- **Quick Add is the one overlay that skips navigate-first focus.** Every other modal/sheet in
  Kyrou opens with a highlighted-but-not-editing field (arrow keys to move, Enter to start
  editing) — Quick Add opens straight into the input with the caret already there, since it's a
  type-immediately surface and making you press Enter first would defeat the point. The first
  `Esc` still only steps back to the non-editing state before a second `Esc` closes the modal.
- Markdown task bodies reuse `parseQuickAdd`, so shared date/time, duration, project, priority,
  tag, and subtask tokens are interpreted the same way when pasting a task list into
  [Today](/features/today)'s Markdown mode.

## Where to start editing

- Adding a new parseable token (e.g. a new syntax) -> `src/lib/nlpParser.ts`, then surface it as a chip in `ParsingChips.tsx`.
- Changing autocomplete behavior -> `useTokenAutocomplete.ts` and the shared `useTypeahead` hook.
- `QuickAddModal.test.ts` in the same folder is the existing test coverage to extend when you touch parsing behavior.
